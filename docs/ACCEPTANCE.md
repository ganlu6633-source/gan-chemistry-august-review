# V2 验收记录（2026-08-12）

## 需求闭环

- 一个 8 位访问码入口，服务端自动识别学生或家长角色，页面不提供角色选择。
- REVIEW 与 CLASS_QUIZ 共用 studentId、技能、题库和证据层；首轮 5—7 题，默认必做预算不超过 8，硬上限 10。
- 计划中的过去、今天和未来日期均可进入；加入前日期不算未完成；重做追加 review attempt，不覆盖首轮。
- Skill Level 的 maxLevel 按技能变化；升级需要不同 motherId 证据；遗忘、恢复和教师介入独立记录。
- 学生端只描述已经获得的能力，不做排行榜；家长端喜忧都报但不做心理诊断；教师内部备注严格隔离。
- 教师工作台覆盖课堂记录、课程节点审批、题目审批/停用和一次性访问码重置。
- 每日北京时间 01:00 由 pg_cron 生成前一日汇总。

## 数据验收

- 31 份真实学生档案已私密导入。
- 49 个姓名别名映射到固定 studentId；正式姓名相近者保持独立 ID。
- 3 组明确冲突保留双方来源，未静默覆盖。
- 未知、缺失字段按原始状态保留；需要诊断者没有被虚构 Level。
- 62 个真实角色访问码全部唯一，另有 2 个非个人演示码；明文只在教师私密交付文件中保存。
- 每位真实学生初始化 5 个可点击计划，共 155 条；学段题目均经过 `IN` 范围门控。

## 已知运行约束

- 教师登录邮箱必须位于私密 allowlist；魔法链接回调固定到线上 `/teacher/`。
- GitHub Pages 发布使用根目录生产文件；修改源码后必须重新运行 `pnpm publish:static`。
- 教师魔法链接使用 `/teacher/`，发布脚本会同步生成 `teacher/index.html` 作为 GitHub Pages 直达入口；若认证服务回退到站点根路径，已有教师会话也会自动转入教师工作台。
- 性能顾问仅报告新建索引尚未积累使用统计的 INFO，不是缺索引或安全错误。
